# Air Canvas — نقاشی با حرکت دست

یک برنامهٔ کامل و ماژولار Python برای نقاشی با وب‌کم. شش رنگ، قلم و پاک‌کن،
تنظیم ضخامت، Undo/Redo، انتخاب ابزار با دست یا ماوس و ذخیرهٔ PNG دارد.
رابط برنامه انگلیسی است و راهنمای استفاده و توضیح کد در این فایل فارسی است.

## اجرای سریع روی همین کامپیوتر

در ویندوز روی همین کامپیوتر اجرا:

1. روی **START.bat** دوبار کلیک کن تا حالت وب‌کم باز شود. اگر محیط لازم وجود
   نداشته باشد، راه‌اندازی اولیه به‌طور خودکار اجرا می‌شود.
2. برای اجرای بدون وب‌کم روی **START_MOUSE.bat** دوبار کلیک کن.
3. تصویرهای ذخیره‌شده داخل پوشهٔ **drawings** قرار می‌گیرند.

روی کامپیوتر دیگر ابتدا ZIP را کامل Extract کن. START.bat در صورت نبود محیط
اجرای محلی، setup.bat را اجرا می‌کند. اینترنت برای نصب اولیهٔ کتابخانه‌ها لازم
است. اسکریپت نصب Python 3.14 نسخهٔ ۶۴ بیتی را انتخاب می‌کند؛ اگر این نسخه نباشد،
نصب آن را با Python Installation Manager امتحان می‌کند. اگر مدیر نصب موجود
نبود، Python 3.14 x64 را از [python.org](https://www.python.org/downloads/) نصب کن.
فایل ZIP شامل `.venv` نیست؛ محیط مجازی بین کامپیوترها قابل انتقال نیست.

اجرای مستقیم در PowerShell از داخل پوشهٔ پروژه:

```powershell
.\.venv\Scripts\python.exe run.py
.\.venv\Scripts\python.exe run.py --mouse
```

## روش نقاشی

دست را در فاصلهٔ مناسب و نور کافی جلوی دوربین بگیر تا تمام انگشت‌ها دیده شوند.

| حرکت | نتیجه |
| --- | --- |
| فقط انگشت اشاره باز، وسط و حلقه و کوچک جمع | نقاشی با نوک اشاره |
| اشاره و وسط باز، حلقه و کوچک جمع | انتخاب ابزار؛ نوک اشاره را ۰٫۶۵ ثانیه روی دکمه نگه دار |
| سایر حالت‌ها، مانند مشت یا کف دست باز | برداشتن قلم و توقف نقاشی |
| بیرون رفتن دست از تصویر | قطع مسیر؛ هنگام برگشت خط اتصال کشیده نمی‌شود |

وضعیت شست در تشخیص ژست دخالت ندارد. راست‌دست و چپ‌دست هر دو می‌توانند کار کنند.
برای انتخاب دوبارهٔ همان دکمه، ابتدا نشانگر را از آن بیرون ببر و دوباره وارد شو.
در حالت DRAW، ورود به نوار ابزار باعث رسم روی آن نمی‌شود. انتخاب ابزار با ماوس
در حالت وب‌کم هم در دسترس است.

در حالت ماوس، روی قسمت سفید کلیک کن و با نگه داشتن دکمهٔ چپ بکش.
اگر دوربین یا مدل قابل استفاده نباشد، برنامه به حالت ماوس برمی‌گردد؛ پیام
خطای دقیق در پنجرهٔ کنسول چاپ می‌شود. با کلید M می‌توان دوباره حالت دست را امتحان کرد.

## دکمه‌ها و میان‌برها

| کلید / ابزار | کاربرد |
| --- | --- |
| 1 تا 6 | رنگ؛ انتخاب رنگ، پاک‌کن را هم به قلم تبدیل می‌کند |
| P / PEN | قلم |
| E / ERASE | پاک‌کن؛ قطر آن سه برابر ضخامت قلم است |
| + و - | ضخامت قلم از ۲ تا ۴۸ پیکسل |
| Z / UNDO | برگشت یک حرکت کامل، تا ۲۰ مرحله |
| Y / REDO | اجرای دوباره |
| C / CLEAR | پاک‌کردن بوم؛ با Z قابل برگشت است |
| S / SAVE | ذخیرهٔ دو فایل PNG |
| B / WHITE یا CAMERA | تغییر پس‌زمینهٔ نمای بوم |
| Space | توقف/ادامهٔ رسم؛ انتخاب ابزار و ذخیره همچنان ممکن است |
| M | تغییر حالت دست/ماوس |
| F | روشن/خاموش کردن آینه‌ای بودن دوربین |
| Q یا Esc | خروج |

هنگام استفاده از میان‌بر، پنجرهٔ Air Canvas فعال و زبان کیبورد **English** باشد.
در حالت ماوس، اگر دوربینی فعال نباشد، دکمهٔ CAMERA همچنان پس‌زمینهٔ سفید نشان می‌دهد.

## ذخیرهٔ تصویر

هر بار SAVE دو فایل با نام یکتا و زمان ذخیره تولید می‌کند:

- `canvas_...png`: فقط نقاشی، روی پس‌زمینهٔ سفید.
- `canvas_..._transparent.png`: همان نقاشی با کانال Alpha و پس‌زمینهٔ شفاف.

تصویر دوربین، نشانگر و نوار ابزار وارد فایل خروجی نمی‌شوند. خروجی ۹۶۰×۵۲۰ پیکسل
است. پاک‌کن واقعاً Alpha را حذف می‌کند؛ رنگ سفید روی تصویر نمی‌کشد.
اگر هنگام خروج، بوم تغییر ذخیره‌نشده و دارای نقاشی داشته باشد، خودکار ذخیره می‌شود.
برای حفظ نقاشی پس از بسته‌شدن اجباری سیستم، حین کار S را بزن.

## ساختار پروژه و توضیح کد

```text
air_canvas/
├── START.bat                 اجرای اصلی ویندوز
├── START_MOUSE.bat           اجرا بدون دوربین
├── setup.bat / bootstrap.py  ساخت محیط مجازی و نصب
├── run.py                   نقطهٔ ورود ساده
├── requirements.txt         سه وابستگی مستقیم با نسخهٔ مشخص
├── requirements-lock.txt    تمام نسخه‌های نصب‌شده در محیط تست
├── README_FA.md
├── VALIDATION_FA.md          محدوده و نتیجهٔ تست واقعی
├── preview.png              نمونهٔ رابط با نقاشی تولیدشده در کد
├── air_canvas/
│   ├── __main__.py           آرگومان‌های خط فرمان و بررسی سلامت
│   ├── config.py             ابعاد، مسیرها و پالت رنگ
│   ├── app.py                کنترل ورودی و حلقهٔ اجرای برنامه
│   ├── camera.py             بازکردن، دریافت فریم و آزادکردن دوربین
│   ├── tracking.py           مدل MediaPipe و استخراج ۲۱ نقطهٔ دست
│   ├── gestures.py           ژست، پایداری ورود به رسم و انتخاب با مکث
│   ├── canvas.py             بوم شفاف، تاریخچه، پاک‌کن و ذخیره
│   └── ui.py                 رسم رابط، نوار ابزار و پیش‌نمایش دست
├── models/
│   ├── hand_landmarker.task  مدل آمادهٔ Google، حدود ۷٫۸ مگابایت
│   └── MODEL_INFO.md
├── drawings/                خروجی نقاشی‌ها
└── tests/                   تست‌های بدون نیاز به وب‌کم
```

زنجیرهٔ اجرا: `run.py → __main__.main → AirCanvasApp.run`.
در حالت وب‌کم، `Camera.read` فریم را آینه‌ای و با برش مرکزی به ۹۶۰×۶۰۰ تبدیل
می‌کند؛ تصویر کشیده نمی‌شود. `HandTracker.detect` تصویر BGR را به RGB تبدیل
می‌کند و به HandLandmarker در حالت VIDEO می‌دهد. زمان هر فریم صعودی است.
`classify_hand` با زاویهٔ بندها و فاصله از مچ، وضعیت چهار انگشت را تعیین می‌کند.
`GestureGate` برای شروع رسم سه فریم پایدار می‌خواهد، ولی توقف رسم فوری است.
`process_hand` لرزش مختصات نوک اشاره را کم می‌کند و `Canvas.draw` مسیر را می‌کشد.
`ui.render` نمای بوم و ابزارها را ترکیب می‌کند.

هر فایل مسئولیت جدا دارد؛ تغییر رنگ‌ها و ابعاد از config.py انجام می‌شود.
برای رزولوشن‌های دیگر، اندازهٔ رابط و محل دکمه‌ها در ui.py را هم متناسب کن.
مدل به‌صورت **بایت از فایل محلی** بارگذاری می‌شود تا مسیرهای فارسی هم کار کنند.
مدل داخل بسته موجود است و برنامه هنگام اجرا چیزی از اینترنت دانلود نمی‌کند.
فقط نصب اولیه و گزینهٔ تعمیر مدل در setup.bat به شبکه نیاز دارند.
فریم‌های دوربین برای استنتاج محلی مصرف می‌شوند و کد برنامه آن‌ها را ارسال نمی‌کند.

## وابستگی‌ها

نسخه‌های تست‌شده: Python **3.14.3 x64**، MediaPipe **1.1.1**،
OpenCV contrib **5.0.0.93** و NumPy **2.5.4** در ویندوز.

- OpenCV contrib: دوربین، رسم و پنجره؛ نسخهٔ استاندارد OpenCV را هم در خود دارد.
- MediaPipe: شبکهٔ از پیش آموزش‌دیدهٔ تشخیص دست. نیازی به آموزش مدل نداری.
- NumPy: آرایهٔ پیکسل‌های بوم و محاسبات تصویر.

کتابخانه‌هایی مانند matplotlib و sounddevice وابستگی MediaPipe هستند؛ نصب‌کننده
خودکار نصبشان می‌کند. از نصب هم‌زمان `opencv-python` یا نسخهٔ headless در همین
محیط خودداری کن چون همگی ماژول `cv2` را فراهم می‌کنند.
برای بازسازی دقیق محیط تست:

```powershell
py -3.14 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-lock.txt
```

## تست و عیب‌یابی

```powershell
# تست منطق بوم، ژست و کنترل برنامه؛ بدون وب‌کم
.\.venv\Scripts\python.exe -m unittest discover -s tests -v

# صحت مدل و استنتاج واقعی روی فریم خالی؛ بدون بازکردن دوربین
.\.venv\Scripts\python.exe -m air_canvas --check

# حالت نمونه؛ بدون دوربین
.\.venv\Scripts\python.exe run.py --demo

# دوربین دوم یا پوشهٔ خروجی دلخواه
.\.venv\Scripts\python.exe run.py --camera 1 --output "D:\My Drawings"

# تعمیر مدل گم‌شده یا خراب، از منبع رسمی و با بررسی SHA-256
.\setup.bat --repair-model
```

اگر وب‌کم باز نشد، برنامهٔ دیگری را که از دوربین استفاده می‌کند ببند و در
Windows Settings → Privacy & security → Camera دسترسی برنامه‌های دسکتاپ را
بررسی کن. برنامه به‌طور پیش‌فرض دوربین شمارهٔ صفر را امتحان می‌کند.

اگر تشخیص دست ناپایدار بود، نور را بیشتر کن، کل دست را در تصویر نگه دار و پشت
دست را زیاد به سمت دوربین نچرخان. زاویهٔ بندها نسبت به تست سادهٔ ارتفاع نوک
انگشت مقاوم‌تر است، اما هم‌پوشانی انگشت‌ها، حرکت خیلی سریع یا دست نیمه‌پیدا
همچنان می‌تواند خطا ایجاد کند. سیستم برای یک دست طراحی شده است.

اگر خطای DLL رخ داد، Python x64 و Microsoft Visual C++ Redistributable x64
را بررسی کن. پیام‌های native مربوط به feedback tensors ممکن است در کنسول
MediaPipe ظاهر شوند؛ نتیجهٔ `--check` ملاک بررسی بارگذاری و استنتاج مدل است.
